# 自动记账平台验收记录

> 验收原则：真实平台验收由**用户操作真机页面与支付**完成，合成样本不代表平台验收；
> 每个平台先以「待确认」模式积累真实样本，验证通过条件后才允许开启自动入账
> （`verifiedApps`）。本文记录各平台的识别路径、真实通过条件与验证结论。

## 通用通过条件

- 采集路径：通知监听 / 无障碍页面文本 / 本机 OCR（可选，打包模型不联网）。
- 采集默认只产生待确认候选；某平台在设置中通过验证（`verifiedApps`）后，金额明确、
  账户绑定有效、方向明确且无冲突的候选才自动入账。
- 可靠凭据（单号键 / 事件键）判重：确认、忽略、关联后同一笔支付重放不入账；
  同额同方向近邻、退款关系不明、缺绑定、历史页面一律待确认。
- P6 起与 AI 页截图草稿共享判重：同账本同日同额同向的 AI 来源账目会把采集候选挡成
  「疑似重复」待确认；截图草稿也会提示候选侧的疑似重复（双向，人工处理）。
- 页面模板只在**已取证的平台/页面**启用，不得外推到通知或其它平台。

## 微信

- **识别路径**：通知监听 + 无障碍账单详情页。
- **通过条件**：账单详情的独立负号金额仅在「页面/OCR 来源 + 微信应用 +
  `当前状态 → 支付成功` + `支付时间` + 交易单号」同时存在时适配，优先于原价/优惠；
  多个不同金额或与实付标签冲突仍待确认。`支付时间` 支持中文年月日与严格日期校验。
- **已验证结论**：账单详情负号金额、支付时间解析已实现并有回归样本；
  **最终真机字段验证未完成**（2026-10 设备测试会话按用户要求结束）。
- **待验证项**：真实支付页端到端（采集 → 候选 → 确认入账）完整走查。

## 支付宝

- **识别路径**：无障碍控件文本（账单详情页）。
- **通过条件**：主体标签 `商户标题 → 独立负号金额 → 交易成功`；完整主体标签包括
  `收款方全称/付款方全称`；`付款方` 不得匹配 `付款方式`；付款方式末尾的
  `查看扣款顺序` 属操作文案，不进入绑定键。屏幕负号金额可暴露为 `支出20元`，
  账单详情模板同时覆盖该金额描述与可见负号格式。
- **已验证结论**：真实控件顺序（脱敏）回归通过；2026-10 真机走查通过。
- **待验证项**：持续观察新版页面改版。

## 京东

- **识别路径**：无障碍 + 可选本机 OCR（订单详情页）。
- **通过条件**：已完成订单模板要求「完成 + 实付款 + 支付时间 + 支付方式 + 订单号」；
  金额取 `实付款 … 合计` 的唯一值，不取共减/到手价/商品原价。OCR 行序按
  line boundingBox 重排（垂直中心排序）；仅纠正已取证标签
  （`o完成`/图标噪声→完成、`支付时闻`→支付时间、实付款行内 `台计`→合计），
  不猜改数字。已取证订单页可由后续窗口/内容事件再次触发 OCR（`elapsedRealtime`
  限频 ≥ 2 秒，切页或关闭开关取消）。精确类名
  `com.jd.lib.ordercenter.taro.OrderDetailActivityTaro` 的空文本控件树可绕过
  「必须先读到支付文本」的截图门禁；订单列表、聊天、其它平台不得套用。
- **已验证结论**：浅色主题实测别名（`订单蝙号/支付万式/©完成`）与深色主题变体、
  坐标重放通过；2026-10 真机走查**临时接受**（精度仍有局限）。
- **待验证项**：更多真实订单页的标签变异；历史订单持续人工确认。

## 拼多多

- **识别路径**：无障碍（`com.xunmeng.pinduoduo.activity.NewPageActivity`）。
- **通过条件**：仅该页面路径追加「已签收 + 实付 + 支付方式 + 订单号 + 下单时间」模板；
  `实付:,134元` 的逗号分隔只在 PDD 归一化；实付优先于单价/优惠。
  已签收历史订单即使金额明确、平台已验证、账户已绑定也保持 `TIME/PENDING`，
  下单/拼单/发货时间不写入 `paidAt`；同订单号重访不新增记录。
- **已验证结论**：真实已签收订单页（脱敏样本）回归通过；2026-10 真机走查通过。
- **待验证项**：无（持续观察改版）。
