# VipLedger 产品与开发总规划

> 本文件是本项目的**权威规划入口**。会话中断后：先读本文第 6 节「进度看板」，再读

> 最后更新：2026-09-24（M0 建库）

## 1. 目标

做一款**本地优先、离线可用**的中文记账 Android App，覆盖市面常见记账软件的基本功能：
多账本、固定两级分类、自定义标签、多资金账户（含借贷与分期）、周期记账、
按标题/备注关键字与分类/时间段搜索、按时间段与分类/标签统计、
可配置云端 AI 的自然语言记账、端侧小模型自动归类、WebDAV 备份与导入导出。

成功标准：能连续 30 天作为主力记账工具使用，数据不丢（本地库 + 可恢复快照），
常见操作（记一笔 / 查一个月支出 / 看分类占比）在 3 次点击内完成。

## 2. 用户与交付形态

- 主要用户：维护者本人 + 小范围分发的朋友；后续可能开源。
- 不做应用商店级的合规改造（通知使用权、短信权限相关能力延后到 v2）。
- 中文界面优先，字符串全部走资源文件，为后续加英文留口子。
- 单用户、单设备主库；WebDAV 只做备份快照，不做多设备双向同步。

## 3. 范围

### 3.1 v1（本主线交付）

| 能力 | 说明 |
|---|---|
| 多账本 | 账本切换与完全隔离（分类/标签/账户/规则都属账本级） |
| 分类 | 固定两级（一级 + 二级），收入/支出/转账各自成树 |
| 标签 | 自定义标签，多标签挂在一笔账上 |
| 资金账户 | 现金/储蓄卡/信用卡/虚拟账户（支付宝、微信、花呗）/应收/应付/贷款 |
| 记账 | 支出、收入、转账、还款、调整；标题、备注、时间、附件 |
| 周期记账 | 每天/每周/每月/每年/每 N 天/每 N 月 + 结束条件；默认生成待确认草稿；支持补记 |
| 借贷与分期 | 额度、账单日、还款日、最低还款；等额本息/等额本金/先息后本/自定义每期；逐期生成与核销；提醒 |
| 搜索 | 标题/备注关键字 + 时间段 + 分类（含子分类）+ 标签 + 账户 + 类型 + 金额区间 |
| 统计 | 自定义与常见时间段；按分类/标签/账户/月/周分组；饼图占比、趋势、下钻明细；导出图片与 CSV |
| 备份恢复 | WebDAV 加密快照（手动 + 定时），浏览远端、恢复、保留策略 |
| 导入导出 | 导出 CSV/JSON；导入支付宝/微信账单 CSV + 通用 CSV 映射向导；去重 |
| AI 自然语言记账 | 可配置 OpenAI 兼容端点（含 Ollama）；本地规则先猜；草稿确认；修正样本沉淀 |

### 3.2 v2 候选

预算（月度总预算 + 分类预算 + 超支提醒）→ 通知栏抓取自动记账 → 短信/账单文件解析 →
桌面小组件（`androidx.glance`，本机已缓存）→ 应用锁（PIN/生物识别）→ xlsx 导出 →
多币种与汇率 → 账本共享评估。

### 3.3 明确不做（v1）

多设备双向同步与冲突合并、多币种与汇率、自建服务端、账单云同步、
在设备上做 LLM 微调、iOS/桌面端。

## 4. 决策记录

| # | 决策 | 结论 | 影响 |
|---|---|---|---|
| D1 | 技术栈 | Kotlin + Jetpack Compose 原生，Gradle 多模块 | 端侧推理与后台任务可控，包体小 |
| D2 | 端侧 AI | 分类小模型（ONNX/线性模型）+ 云端 LLM 抽取 | 不引入端侧 LLM，避免 400MB+ 包体 |
| D3 | 训练方式 | App 内自动训练**默认关闭**；仓库内提供 Python 训练脚本 | 两条路同构，权重格式一致 |
| D4 | WebDAV | 只做备份/恢复快照，单设备主库 | 不实现冲突合并 |
| D5 | 借贷深度 | 账户级负债 + 分期与利息计算 + 提醒 | 需要分期计划与逐期流水 |
| D6 | 币种 | v1 单币种（CNY），金额用整数分 | 汇率表延后 |
| D7 | 分类层级 | 固定两级（`parentId` 自关联，强约束深度 ≤ 2） | UI 与统计按两级汇总 |
| D8 | 分发 | 先自用，不按商店审核做妥协 | 敏感权限能力延后到 v2 |
| D9 | 依赖仓库 | 阿里云镜像（google/central/gradle-plugin/jitpack） | 已实测直连 maven.google.com 超时 |
| D10 | 版本控制 | 本地 `git init`，远端由维护者后续接入 | Trellis 归档/提交依赖 git |
| D11 | 交付节奏 | 按里程碑拆多个 Trellis 任务，每任务独立可验收 | 见第 5 节 |
| D12 | 预算 | 放 v2，不做进 v1 | 首页预留入口位 |
| D13 | 依赖版本矩阵 | Kotlin 2.2.10 + KSP 2.2.10-2.0.2 + Hilt 2.57.2 + AGP 8.13.1 + Gradle 8.14 + Compose BOM 2026.06.01 | 三者互相牵制，见 `docs/DEV-NOTES.md` 第 3 节，升级前必须跑通构建 |
| D14 | Spec 结构 | `.trellis/spec/` 由通用 frontend/backend 占位改为 android 分层 | 规范只写本项目真实约定 |

## 7. 中断恢复流程

1. 读 `.trellis/workflow.md` 与 `trellis-start` 技能，跑 `python ./.trellis/scripts/get_context.py`。
2. 读本文件第 6 节进度看板，确定当前里程碑。
3. 读 `.trellis/tasks/<当前任务>/prd.md` 与 `implement.jsonl`。
4. 读 `docs/ARCHITECTURE.md`（技术约定）与 `docs/DATA-MODEL.md`（表结构）。
5. 读 `git log --oneline -20` 看上次提交停在哪。
6. 继续实现；不要重写已完成的里程碑。

## 8. 风险与未决

| 风险 | 说明 | 缓解 |
|---|---|---|
| 依赖下载不稳 | 直连 `maven.google.com` 已实测超时 | 统一走阿里云镜像；关键库优先用本机缓存版本 |
| Hilt / AGP / Kotlin 相互牵制 | Hilt 2.57 读不了 Kotlin 2.3 元数据；Hilt 2.58 起要求 AGP 9；AGP 9 要求 JDK 25 | 已锁定 Kotlin 2.2.10 + Hilt 2.57.2 + AGP 8.13.1，升级前先跑通构建 |
| 通知/短信权限 | 属敏感权限，商店审核风险 | 放 v2，且默认端侧解析、云端需显式开启 |
| 中文关键字搜索性能 | `LIKE %kw%` 无法用索引 | 先用于十万级数据；不达标再上 FTS5 或应用层倒排 |
| 其他记账 App 导入格式 | 无样本无法适配 | 先做可插拔 preset + 通用映射向导 |

未决问题：

- 应用正式名称与图标（暂用 VipLedger）。
- 远程仓库地址（GitHub / Gitee）由维护者提供。
- 通知抓取的具体厂商模板（v2 需要真机样本）。
