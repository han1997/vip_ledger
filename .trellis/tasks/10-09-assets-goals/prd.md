# P2 资产、储蓄、首页配置

Status: implementation and verification complete; user authorized P2 on 2026-10-10 after approving P0/P1 commits and archive.

- 资产分组：资金、信用、充值（新增类型）、应收应付、贷款、投资；详情、转账、调整、归档，排除净资产标识明确。汇总对同一纳入账户集合取正余额为资产、负余额绝对值为负债，净资产为两者之差。
- 建立可验证资产历史基线，不伪造升级前曲线。
- 储蓄：名称、目标金额、截止日、存入/取回、完成/归档。进度关联实际转账，分配记录不再次改变余额。
- 首页配置按账本持久化：卡片显隐、排序、恢复默认；加入储蓄卡片，默认预算/今日/储蓄/七日。
- 验收：转账及储蓄不虚增净资产；配置和目标完整备份；五 Tab 状态保持。

See docs/FEATURE-ROADMAP.md for shared contracts, acceptance and delivery requirements.

## 本批实施决策
- 五Tab新增资产；分组及账户详情复用现有账户/流水，校准余额写ADJUST差额，转账复用现有编辑器。正负余额使用同一纳入集合。
- 每个储蓄目标绑定一个本账本非负债账户；目标金额>0，截止日可选。存入/取回创建普通TRANSFER并建立唯一txn关联，进度从关联的已确认未删除转账推导。达到目标自动显示已达成，可归档/恢复。关联后禁止修改目标账户。
- 取回不超过目标已存金额；通用账目修改/删除/恢复同样校验关联与非负进度，禁止改成其他类型或脱离目标账户。跨表失败整体回滚；可编辑转账金额，目标进度跟随。
- 首页卡片：预算、今日、储蓄、七日、待处理；默认前四显示，待处理默认隐藏（仍能在原入口查看）。配置按账本保存、可排序/显隐/恢复默认。因用户要求完整备份，此配置用Room表，与普通不需备份的DataStore临时偏好区分。
- schema4增加savings_goal/savings_link/home_card/asset_baseline；迁移为现有账户记录升级时余额及纳入状态，后续新账户首次打开资产页补基线。基线是可验证快照，不伪造过往趋势；P7再实现历史曲线。
- 旧快照1–3缺新表时为空；新格式4包含四表、预算和所有旧数据。恢复旧格式后首次资产观察补基线。
