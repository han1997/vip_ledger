## 记账流程（核心发现）

**入口深度极短**：
打开 app → 首页 → **1 下点击**到达记账页（新建记账状态）。

**表单结构**（从上到下）：
1. 类型选择：`支出 | 收入 | 转账 | 债务`（FilterChip 横向排列）
2. 一级分类选择（横向 Chip，点选后展开二级）
3. 二级分类点选
4. 标签选择、账户选择
5. 保存

**分类选择机制**：
- 类型 → 一级分类 → 二级分类，两级之间有明确的父子关系
- 一级分类点选后，才出现二级分类选项
- 不是全量两级同时铺开，而是**按需展开**，视觉上清晰

## 对我们重设计的可借鉴点

1. **分类层级按需展开**（Parent Category → Child Category）：
   我们现状：两级 FilterChip 全在一个 FlowRow 里平铺，父分类和子分类同时可见
   建议：`CategorySection` 改为一级的 `SectionLabel + FlowRow`，子分类在父分类选中后才出现（`animateVisibility` 或条件渲染）

2. **入口效率**：
   我们 FAB 已是 1 下到达，满足「打开 app → 记账」的要求（和一木记账一致）
   但 TxnEditScreen 内仍有优化空间（见 Decision 7）

3. **类型选择在最前**：
   一木记账把类型（支出/收入/转账/债务）放在最顶部
   我们现状也放在顶部，但 5 个类型混在一起（增加了 DEBT_REPAY 和 ADJUST），视觉密度更高
   建议按频率重排 + 等宽 Chip

4. **账户/标签选择**：
   一木记账有独立的账户选择和标签选择（横向 Chip 或独立 UI）
   我们现状的 AccountSection 用 FilterChip，处理了转出+转入账户（较复杂）
   建议：AccountSection 的目标账户（toAccountId）当不需要时不渲染（当前已有 `requiresTargetAccount` 判断）
