# 原型优先 UI 开发契约(Prototype-First UI Contract)

> **适用范围**:所有 Compose UI 开发与改动。原型(`docs/ui-prototype/`)是 UI 的唯一事实来源;
> 本契约规定「原型 → 实现」的过程纪律、范围边界与验收标准。
> 原型自身的硬性规则(无假按钮、页面不跳出手机壳、禁止浏览器弹窗等)见 `ui.md`「原型优先」一节。

## 契约条款

### 1. 一切 UI 基于已确认原型

- 所有 UI 必须基于**已确认**的原型版本(`BASELINE.md` 中状态为「已确认」的基准);
  「待用户确认」的版本不得作为实现依据。
- 缺少页面、交互或必要状态时,**先补原型并经用户确认**,再写 Compose 代码;
  不允许「边写代码边定设计」。

**验证**:实现前核对 `BASELINE.md` 当前基准的 SHA-256 与文件实际哈希一致。

### 2. 范围不增不减

- 原型未覆盖的**现有功能不能删除**:原型没画的页面/入口,真机上仍要保留,
  除非用户明确说删。
- 原型展示的**新能力不能默认扩大开发范围**:原型里出现的新字段、新交互
  (如账户卡号)只代表设计意向,是否落库、是否开发需单独确认,不得因原型先行改 schema。

**验证**:实现 PR 的范围 = 已确认原型范围;超出或裁剪都要在任务里写明并经确认。

### 3. 状态完整覆盖

- 每个界面必须完整覆盖:**加载、空态、错误、重试、执行中、禁用、危险操作确认**。
- 原型也应尽量呈现这些状态(可用演示数据);原型呈现不了的(如真实网络错误),
  实现时按 `error-handling.md` 的口径补齐,并在验收时逐项演示。

**验证**:交付清单里逐项列出上述状态在真机上的表现;缺一项即不通过。

### 4. 单一设计规则来源

- 统一设计令牌与共享组件:**一律走 `core:designsystem`**(`VipLedgerTokens`、
  `GroupCard`/`ActionRow`/`PrimaryButton` 等),不保留两套互相冲突的设计规则。
- 禁止在 feature 里写死颜色/间距/圆角字面量;原型 token → Compose 的映射
  以应用内「设计系统与 Compose 映射」为准。

**验证**:`grep -rn "Color(0x" feature/` 零命中(语义色/强调色全部取自 designsystem)。

### 5. 版本记录

- **原型变更、用户确认、实现与验收截图**都需要版本记录:
  - 原型侧:`BASELINE.md` 登记版本、变更内容、文件 SHA-256、确认状态;
  - 实现侧:任务 PRD 记录对应原型版本,验收时附真机截图证据。

**验证**:每个 UI 任务的归档材料里能回答「基于哪个原型版本、谁确认的、真机截图在哪」。

### 6. 平台要求优先

- **Android 安全区域**(状态栏/导航栏/IME insets)、**返回**(`BackHandler` + 未保存确认)、
  **系统选择器**(SAF 文件/目录选择)、**权限**(运行时申请与拒绝态)、**无障碍**
  (触摸目标 ≥ 48dp、语义、对比度)优先于原型的视觉呈现。
- 原型无法表达这些平台行为属正常;但**明显偏差**(如原型要求全屏沉浸、平台不允许)
  需要向用户确认后再实现。

**验证**:验收时检查 insets/返回/权限拒绝路径;无障碍用 TalkBack 或语义检查抽查。

### 7. 编译通过 ≠ UI 验收通过

- 编译/测试通过只是门槛,**UI 验收必须做**:
  - **明暗两套主题**逐屏核对(hero/彩色容器上的文字对比度 ≥ 4.5:1);
  - **屏幕适配**:小屏(如 360dp)/大屏/横屏下布局不破(编辑页尤其要复核「不滑动」);
  - **交互验收**:按原型 `smoke-test.cjs` 的动作清单在真机逐项走一遍。

**验证**:验收截图含明暗两套、至少两种屏宽;交互走查记录在任务里。

### 8. 像素级实现

- 像素级 UI 实现需**对照已确认原型逐项核对**:间距(4dp 网格)、圆角、字号、字重、
  颜色、选中/按压/禁用态。发现原型不合理时,先改原型并重新确认,不在实现时私自偏离。

**验证**:实现截图与原型截图并排比对;偏差项要么修实现、要么改原型重新确认。

### 9. 桌面图标与原型同源

- 桌面启动图标属于设计基准的一部分:必须与应用 UI 同一设计语言(配色、渐变、金色发丝
  描边),不得沿用与基准脱节的默认或旧图标。
- 图标变更时**双向同步**:实现侧更新 `app/src/main/res` 自适应图标
  (背景 / 前景 / monochrome 三层),原型侧同步更新 brand-mark,并按第 5 条在
  `BASELINE.md` 登记新版本待确认;只改一边视为违约。
- 图标语言优先几何/符号(小尺寸不发糊);避免在小尺寸下难以辨清的中文单字
  (2026-10-13:「账」字方案被否,改用铜钱几何方案)。

**验证**:实现图标资源、原型 brand-mark、BASELINE 版本记录三处一致。

## 违约处理

- 任何一条不满足 → 该 UI 变更**不得合入**;已合入的按违约项回滚或补齐。
- 与本契约冲突的旧规则,以本契约为准;发现冲突时更新旧规则而不是绕开契约。

## 交付前快速清单

- [ ] 基于 `BASELINE.md` 已确认版本(哈希核对)
- [ ] 范围 = 原型范围,无增删
- [ ] 加载/空态/错误/重试/执行中/禁用/危险确认 全覆盖
- [ ] 全部走 designsystem token 与组件,无字面量
- [ ] BASELINE/任务里能回答「哪个版本、谁确认、截图在哪」
- [ ] insets/返回/权限/无障碍 检查过,偏差已确认
- [ ] 明暗主题 + 屏幕适配 + 交互走查 完成
- [ ] 与原型并排像素比对完成
- [ ] 桌面图标与原型 brand-mark 同源一致(资源三层 + BASELINE 版本记录)
